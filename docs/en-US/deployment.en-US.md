# NihongoHub Server Deployment Guide

This guide explains how to deploy, configure, and maintain NihongoHub Server.

> **Note:** NihongoHub Server is currently in the Demo stage and has not undergone complete production testing. Do not use it in production environments or for storing important data.

## 1. Requirements

NihongoHub Server is built with ASP.NET Core Minimal API and .NET 10.

Prepare the runtime environment according to the type of package you use:

- Framework-dependent packages require the corresponding .NET 10 Runtime.
- Self-contained packages generally do not require a separately installed .NET Runtime.
- To build the project from source, install the .NET 10 SDK.

We recommend deploying the application in a dedicated directory rather than running it directly from the source directory.

## 2. Starting the Server

Obtain a runnable release package, place the application files in a dedicated deployment directory, and make sure the account running the server has the required file system permissions.

On its first launch, the application creates a `Config` directory under the application runtime directory. It also generates the default configuration file when necessary.

The default directory structure is:

```text
Application directory/
├── NihongoHub.Server
└── Config/
    ├── config.json
    ├── nihongo.db
    └── initial-admin-credentials.txt
```

The executable filename may vary depending on the target platform and build method.

## 3. First Launch and Default Administrator

If the database contains no users, the application automatically creates a default administrator account:

- Username: `admin`
- Password: randomly generated during the initial setup.

The initial credentials are written to:

```text
Config/initial-admin-credentials.txt
```

After the first launch, retrieve the credentials from this file and store them securely.

We recommend signing in and changing the administrator password as soon as possible. After you no longer need the plaintext credentials file, remove it or store it in a secure location.

**Do not upload this file to a public repository, share it with others, or store it in an untrusted backup location.**

## 4. Configuration

The default configuration file is:

```text
Config/config.json
```

It controls the server listening address, port, HTTPS settings, database filename, and JWT settings.

The main configuration options are:

| Section | Option | Default or Description |
|---|---|---|
| Server | Host | `0.0.0.0` |
| Server | Port | `5000` |
| Server | HttpsEnable | `false` |
| Server | PfxPath | Path to the HTTPS certificate file |
| Server | PfxPassword | Certificate password |
| Database | FileName | `nihongo.db` |
| Jwt | Key | Randomly generated during initial setup |
| Jwt | Issuer | `NihongoHub` |
| Jwt | ExpireMinutes | `10080` minutes, or 7 days |

Edit the configuration file generated by the application. Keep the expected field structure and data types.

The current configuration loader rejects unrecognized configuration fields. Do not add unsupported options.

### 4.1 Server Listening

The default settings are:

- Address: `0.0.0.0`
- Port: `5000`
- HTTPS: Disabled

`0.0.0.0` means that the server listens on all available network interfaces.

The default configuration uses HTTP. It is intended only for testing on a trusted local network or private network. Do not expose the default HTTP service directly to the public internet without additional security measures.

### 4.2 HTTPS

To enable the built-in HTTPS listener, configure:

- `HttpsEnable`: Set to `true`.
- `PfxPath`: Set the path to a valid PFX certificate file.
- `PfxPassword`: Set the certificate password.

Make sure the certificate file exists and that the account running the application can read it.

Alternatively, a reverse proxy can provide HTTPS at the network boundary. In this setup, restrict access to the application listener and ensure that the connection between the proxy and the application is appropriately protected or confined to a trusted network.

Client-to-server communication carrying account passwords or tokens should use a protected connection.

### 4.3 Database

The default database file is:

```text
Config/nihongo.db
```

The application uses LiteDB.

The database contains user accounts and vocabulary-related data. Restrict file system access to prevent unauthorized users from reading or modifying it.

## 5. JWT and Credential Protection

During initial setup, the application generates a random JWT signing key and stores it in the configuration file.

Keep the following in mind:

- Do not disclose `Jwt.Key`.
- Do not upload the configuration file to a public repository.
- Do not commit certificates, certificate passwords, or initial administrator credentials.
- Changing the JWT signing key invalidates tokens signed with the previous key.
- The default token lifetime is 7 days.

In the current version, changing a user's password does not automatically revoke tokens that were issued to that user earlier. Therefore, changing a password should not be considered an immediate way to terminate all existing sessions.

## 6. Network Security Recommendations

Before deploying on a public or untrusted network, consider at least the following measures:

- Use HTTPS to protect communication between clients and the server.
- Restrict unnecessary network access through a firewall or reverse proxy.
- Do not expose database files, configuration files, or other internal files to the public internet.
- Restrict file system permissions for the application and configuration directories.
- Back up the database and necessary configuration files regularly.
- Do not store passwords or tokens in untrusted terminals, logs, or public discussions.

The current server implementation does not include endpoint-level rate limiting for login requests. Before public deployment, consider adding access restrictions and appropriate protection at the reverse proxy or network boundary.

## 7. Backup and Updates

Before updating the application or changing its configuration, we recommend stopping the service and backing up:

- `Config/nihongo.db`
- `Config/config.json`
- Any required certificate files and related configuration.

Store backups in a location with appropriate access restrictions.

When updating, replace the application files with the new version while retaining the configuration and database files that must be preserved.

The project is still in the Demo stage. Database structures and configuration formats may change. Back up your data before upgrading, and do not assume that all versions are fully compatible.

## 8. Troubleshooting

### The Application Does Not Start

Check the following:

- Whether the runtime environment satisfies the .NET Runtime requirements.
- Whether the application directory has the required file permissions.
- Whether `Config/config.json` contains valid JSON.
- Whether configuration fields and data types match the current application requirements.
- If HTTPS is enabled, whether the PFX file exists and the certificate password is correct.

### The API Cannot Be Reached

Check the following:

- Whether the application has started successfully.
- Whether the listening address and port are correct.
- Whether the firewall allows traffic on the configured port.
- If a reverse proxy is used, whether its forwarding configuration is correct.

### Login Fails

Check whether the administrator username and password are correct.

If this is the first launch, check whether the following file has been generated:

```text
Config/initial-admin-credentials.txt
```

If the file does not exist, do not assume that the default password is empty. Check the application startup logs and database initialization status.
