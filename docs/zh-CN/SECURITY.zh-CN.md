# 安全政策

## 项目安全状态

NihongoHub Server 目前处于 Demo 开发阶段，尚未经过完整的生产环境安全审计，也不承诺适用于生产环境或重要数据处理场景。

本项目会认真评估与本仓库代码有关的安全问题，但目前由单一维护者维护，无法承诺固定的响应时间或修复期限。

## 报告安全漏洞

如果你发现了可能影响 NihongoHub Server 的安全漏洞，请优先通过以下任一私密渠道联系维护者。

### 方式一：GitHub Private Vulnerability Reporting

请在本仓库的 **Security / Advisories** 页面中选择 **Report a vulnerability**，通过 GitHub 的私密漏洞报告功能提交。

### 方式二：电子邮件

请发送邮件至：

**egoisticelily@gmail.com**

建议邮件主题：

`[NihongoHub Security] 安全问题简述`

请勿通过公开 Issue、Pull Request 或其他公开讨论渠道披露尚未修复的漏洞。

## 报告内容

为了帮助维护者判断和复现问题，建议尽可能提供以下信息：

- 受影响的分支、版本或 Git Commit。
- 运行环境，例如操作系统、.NET 运行时版本和部署方式。
- 漏洞涉及的 API、功能或代码位置。
- 漏洞的触发条件及复现步骤。
- 可能造成的影响，例如未授权访问、数据泄露或权限绕过。
- 必要的验证材料或概念验证代码。

提交日志、配置片段或其他材料前，请先删除密码、JWT、密钥、用户数据和其他敏感信息。

## 漏洞处理与披露

维护者收到报告后，将根据问题的可复现性、影响范围和实际风险进行评估。

在维护者完成评估并有机会处理问题之前，请不要公开披露漏洞细节，也不要利用漏洞访问、修改或破坏他人的数据和服务。

对于确认的问题，维护者可能会通过修复代码、更新文档或发布安全公告等方式进行处理。由于项目目前由单一维护者维护，不保证所有报告都能在固定期限内得到答复或修复。

## 适用范围

本政策主要适用于本仓库维护的 NihongoHub Server 源代码及其官方项目内容。

基于本项目创建的 Fork、二次开发版本，以及由第三方自行部署和维护的服务，其代码修改、运行环境、配置和运营安全由相应的 Fork 维护者或服务运营者负责。

如果问题仅存在于第三方修改的代码或第三方部署环境中，请联系对应的维护者或运营者。
