# API Code 编号规范

> **规范版本：** 0.1.0 Bate
> **适用范围：** NihongoHub 后端 HTTP API

API Code 是 NihongoHub 自行定义的应用层代码，用于标识 API 操作结果及具体错误原因，便于客户端识别和处理。

API Code 与 HTTP Status Code 相互独立：HTTP Status Code 遵循 HTTP 规范，表示 HTTP 请求的处理结果；API Code 表示 NihongoHub 内部约定的具体结果。客户端应根据 API Code 判断具体错误，不应将两者混用。

## 1. 编号规则

API Code 使用整数，按照功能模块划分编号区间。

| 编号范围 | 类别 |
|---|---|
| `0` | 成功 |
| `1000–1099` | 通用请求错误 |
| `1100–1199` | 身份认证错误 |
| `1200–1299` | 权限错误 |
| `2000–2099` | 用户管理 |
| `3000–3099` | 单词管理 |
| `4000–4099` | 单词本管理 |
| `5000–5099` | 学习与检测 |
| `9000–9099` | 服务器内部错误 |

编号一经确定，其含义不得随意更改；未列出的编号保留，供后续功能扩展。

## 2. 当前 API Code

### 2.1 成功

| Code | 含义 |
|---:|---|
| `0` | 操作成功 |

### 2.2 通用请求错误（1000–1099）

| Code | 含义 |
|---:|---|
| `1000` | 请求参数无效 |
| `1001` | 请求体为空 |
| `1002` | JSON 格式错误 |
| `1003` | 缺少必要参数 |
| `1004` | 参数值不符合要求 |
| `1005` | 不支持的请求格式 |

### 2.3 身份认证错误（1100–1199）

| Code | 含义 |
|---:|---|
| `1100` | 身份认证失败 |
| `1101` | 用户名或密码错误 |
| `1102` | Token 缺失 |
| `1103` | Token 无效 |
| `1104` | Token 已过期 |
| `1105` | Token 尚未生效 |
| `1106` | Token Claims 无效 |
| `1107` | 用户身份已失效 |

补充规定：

- 登录时，用户名不存在和密码错误统一返回 `1101`，不向客户端区分具体原因。
- 用户被禁用、删除，或数据库中的角色与 Token 不一致时，身份验证失败，返回 `1107`。
- 数据库查询异常不属于身份认证失败，应使用服务器内部错误代码。

### 2.4 权限错误（1200–1299）

| Code | 含义 |
|---:|---|
| `1200` | 无权执行此操作 |
| `1201` | 需要管理员权限 |
| `1202` | 无权访问该资源 |

### 2.5 用户管理（2000–2099）

| Code | 含义 |
|---:|---|
| `2000` | 用户操作失败 |
| `2001` | 用户不存在 |
| `2002` | 用户名已被使用 |
| `2003` | 用户已被禁用 |
| `2004` | 用户数据无效 |
| `2005` | 不允许执行该用户操作 |

登录场景中的账号状态不应直接返回 `2003`，应按照身份认证错误规则处理。

### 2.6 单词管理（3000–3099）

| Code | 含义 |
|---:|---|
| `3000` | 单词操作失败 |
| `3001` | 单词不存在 |
| `3002` | 单词数据无效 |
| `3003` | 无权操作该单词 |
| `3004` | 单词关联操作失败 |

### 2.7 单词本管理（4000–4099）

| Code | 含义 |
|---:|---|
| `4000` | 单词本操作失败 |
| `4001` | 单词本不存在 |
| `4002` | 单词本数据无效 |
| `4003` | 无权操作该单词本 |
| `4004` | 单词本关联操作失败 |
| `4005` | 单词与单词本关联已存在 |

### 2.8 学习与检测（5000–5099）

该编号区间暂时保留，尚未启用。相关代码将在学习与检测功能开发时确定。

### 2.9 服务器内部错误（9000–9099）

| Code | 含义 |
|---:|---|
| `9000` | 服务器内部错误 |
| `9001` | 数据库操作失败 |
| `9002` | 未知异常 |
| `9003` | 服务器配置错误 |
| `9004` | 内部业务处理失败 |

服务器内部错误的详细信息仅记录在服务端日志中，不应通过 API 响应向客户端暴露异常堆栈、数据库路径或其他内部实现细节。

## 3. 使用约定

- `code = 0` 表示操作成功；非零值表示具体的错误或失败结果。
- 同一个 Code 始终表示同一种含义，不得在不同 API 中重复赋予其他含义。
- 批量操作出现部分成功时，其响应方式和错误信息需要由对应 API 单独约定。
