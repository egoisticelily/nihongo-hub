# NihongoHub Server 部署指南

本文介绍 NihongoHub Server 的基本部署、首次启动、配置和维护方式。

> **注意：** NihongoHub Server 目前处于 Demo 阶段，尚未经过完整的生产环境测试。请勿将其用于生产环境或存储重要数据。

## 1. 部署准备

NihongoHub Server 基于 ASP.NET Core Minimal API 和 .NET 10 开发。

部署前请根据所使用的发布包准备相应的运行环境：

- 使用依赖框架的发布包时，需要安装对应的 .NET 10 Runtime。
- 使用自包含发布包时，通常不需要另外安装 .NET Runtime。
- 如果需要自行编译，请安装 .NET 10 SDK。

建议将程序部署在专用目录中，不要直接在 Git 源码目录中运行服务。

## 2. 启动程序

获取可运行的发布包后，将程序文件放入专用部署目录，并确保运行程序的用户拥有必要的目录读写权限。

首次启动时，程序会在应用程序运行目录下创建 `Config` 目录，并在需要时生成默认配置文件。

默认目录结构如下：

```text
应用程序目录/
├── NihongoHub.Server
└── Config/
    ├── config.json
    ├── nihongo.db
    └── initial-admin-credentials.txt
```

实际程序文件名称可能随发布平台和构建方式不同而变化。

## 3. 首次启动与默认管理员

当数据库中不存在任何用户时，程序会自动创建一个默认管理员账号：

- 用户名：`admin`
- 密码：程序首次初始化时随机生成。

初始账号和密码会写入：

```text
Config/initial-admin-credentials.txt
```

首次启动后，请及时查看该文件，并妥善保存登录凭据。

建议完成首次登录后立即修改默认管理员密码，并妥善保管或删除不再需要的明文凭据文件。

**请勿将该文件上传到公开仓库、发送给他人或放入不受信任的备份位置。**

## 4. 配置文件

默认配置文件：

```text
Config/config.json
```

配置文件用于设置服务器监听地址、端口、HTTPS、数据库文件名称和 JWT 等信息。

主要配置项如下：

| 配置类别 | 配置项 | 默认值或说明 |
|---|---|---|
| Server | Host | `0.0.0.0` |
| Server | Port | `5000` |
| Server | HttpsEnable | `false` |
| Server | PfxPath | HTTPS 证书文件路径 |
| Server | PfxPassword | HTTPS 证书密码 |
| Database | FileName | `nihongo.db` |
| Jwt | Key | 首次初始化时随机生成 |
| Jwt | Issuer | `NihongoHub` |
| Jwt | ExpireMinutes | `10080` 分钟，即 7 天 |

请直接修改程序生成的配置文件，并保留其字段结构和数据类型。

当前配置加载对无法识别的配置字段采取严格处理，因此不要随意添加程序不支持的配置项。

### 4.1 服务器监听

默认配置：

- 地址：`0.0.0.0`
- 端口：`5000`
- HTTPS：关闭

`0.0.0.0` 表示监听所有可用网络接口。

默认配置使用 HTTP，仅适合受信任的本地或内网测试环境。不要在没有额外安全措施的情况下直接将默认 HTTP 服务暴露到公网。

### 4.2 HTTPS

如果需要启用程序内置 HTTPS，应配置：

- `HttpsEnable`：设为 `true`。
- `PfxPath`：指定有效的 PFX 证书文件。
- `PfxPassword`：填写证书密码。

请确保证书文件存在，并且运行程序的用户具有读取权限。

也可以在可信网络边界使用反向代理提供 HTTPS，并限制应用程序本身的网络访问范围。

无论采用哪种方式，客户端与服务器之间传输账号密码和 Token 时，都应使用受保护的连接。

### 4.3 数据库

默认数据库文件：

```text
Config/nihongo.db
```

数据库使用 LiteDB。

数据库文件包含用户账号和词汇等业务数据。请限制文件访问权限，避免未经授权的用户读取或修改。

## 5. JWT 与凭据保护

首次初始化时，程序会生成随机 JWT 密钥，并将其保存在配置文件中。

请注意：

- 不要公开 `Jwt.Key`。
- 不要将配置文件上传到公开仓库。
- 不要将证书文件、证书密码或管理员初始密码提交到版本控制系统。
- 更换 JWT 密钥会导致此前签发的 Token 无法继续通过签名验证。
- 默认 Token 有效期为 7 天。

当前版本修改用户密码后，不会主动撤销该用户此前已经签发的 Token。因此，修改密码不应被视为立即注销所有已有登录会话的措施。

## 6. 网络安全建议

在公网或不受信任的网络中部署前，请至少考虑以下事项：

- 使用 HTTPS 保护客户端与服务器之间的通信。
- 通过防火墙或反向代理限制不必要的网络访问。
- 不要向公网开放数据库文件、配置文件或其他内部文件。
- 限制服务器程序和配置目录的文件系统访问权限。
- 定期备份数据库和必要的配置文件。
- 不要在不受信任的终端、日志或公开讨论中保存密码和 Token。

当前版本未发现登录接口自身具备请求限流保护。公网部署前，应在反向代理或其他网络边界增加必要的访问限制和防护。

## 7. 备份与更新

在更新程序或调整配置之前，建议先停止服务，并备份：

- `Config/nihongo.db`
- `Config/config.json`
- 必要的证书文件及相关配置

请将备份存放在受访问权限保护的位置。

更新时，使用新的程序文件替换旧版本，并保留需要继续使用的配置和数据库文件。

由于项目处于 Demo 阶段，数据库结构和配置格式可能发生变化。升级前请先备份数据，不要假定不同版本之间始终兼容。

## 8. 故障排查

### 程序无法启动

请检查：

- 当前运行环境是否满足 .NET Runtime 要求。
- 程序目录是否具有读写权限。
- `Config/config.json` 是否为有效 JSON。
- 配置字段和数据类型是否符合当前程序要求。
- 启用 HTTPS 时，PFX 文件是否存在，证书密码是否正确。

### 无法访问 API

请检查：

- 程序是否已正常启动。
- 当前监听地址和端口是否正确。
- 防火墙是否允许对应端口通信。
- 如果使用反向代理，请检查代理转发配置。

### 无法登录

请检查管理员账号和密码是否正确。

如果是首次启动，请确认是否已经生成：

```text
Config/initial-admin-credentials.txt
```

如果该文件不存在，不要直接假设默认密码为空。请检查程序启动日志及数据库初始化状态。
