# コントリビューションガイド

NihongoHub Server に関心を持っていただき、ありがとうございます。

本プロジェクトは現在 Demo 開発段階であり、個人で開発・メンテナンスしています。Issue による問題報告や提案を歓迎します。また、Pull Request も受け付けていますが、すべての外部からの変更はメンテナーによる確認が必要であり、マージを保証するものではありません。

## Issue の作成

Issue を作成する際は、可能な範囲で次の情報を記載してください。

- 問題が発生している機能または API
- 使用しているバージョン、ブランチ、または Git Commit
- 実行環境
- 問題を再現する手順
- 実際の結果と期待する結果

公開 Issue にパスワード、JWT、秘密鍵、証明書、ユーザーデータなどの機密情報を含めないでください。

セキュリティ上の脆弱性については、[SECURITY.md](SECURITY.ja-JP.md) に記載されている非公開の報告方法を利用してください。

## Pull Request の提出

規模の大きい変更を行う場合は、実装を始める前に Issue を作成し、変更の目的と実装方針について相談することを推奨します。これにより、作業の重複やプロジェクトの設計方針と合わない変更を避けやすくなります。

Pull Request を提出する際は、次の点に注意してください。

- 変更の目的と範囲を説明する。
- 変更範囲をできるだけ限定し、無関係なリファクタリングを含めない。
- 既存のコードスタイルと命名規則に従う。
- API、データ構造、設定の変更を明確に説明する。
- 適切な検証手順を提示し、実際に行ったテスト内容を記載する。

メンテナーは修正を依頼する場合があります。また、プロジェクトの計画や設計方針に基づいて、変更を受け入れない場合もあります。

## コードとセキュリティに関する要件

次の情報やファイルをコミットしないでください。

- 実際のユーザーパスワードやアカウント情報
- JWT 署名鍵やその他のアクセス用秘密情報
- 秘密鍵、証明書、証明書のパスワード
- 個人情報や実際のユーザーデータベース
- 今回の変更に関係のないビルド成果物や実行時ファイル

開発やテストには架空のデータを使用してください。

## 互換性

本プロジェクトはまだ Demo 段階であり、API、データ構造、設定形式が変更される可能性があります。

API、データ構造、設定形式に影響する変更を行う場合は、既存のクライアントやデプロイ環境への影響を明確に説明してください。
