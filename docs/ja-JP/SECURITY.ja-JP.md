# セキュリティポリシー

## プロジェクトのセキュリティ状況

NihongoHub Server は現在、Demo 開発段階です。完全なセキュリティ監査は実施されておらず、本番環境や重要なデータを扱うシステムでの利用を保証するものではありません。

メンテナーはセキュリティに関する報告を重視しています。ただし、本プロジェクトは個人でメンテナンスしているため、回答や修正の期限を保証することはできません。

## 脆弱性の報告

NihongoHub Server にセキュリティ上の脆弱性と思われる問題を発見した場合は、次のいずれかの非公開チャネルから報告してください。

### 方法 1：GitHub Private Vulnerability Reporting

本リポジトリの **Security / Advisories** ページにある **Report a vulnerability** から、GitHub の非公開脆弱性報告機能を利用してください。

### 方法 2：メール

次のメールアドレスに報告してください。

**egoisticelily@gmail.com**

メールの件名は、次の形式を推奨します。

`[NihongoHub Security] 問題の概要`

修正されていない脆弱性の詳細を、公開 Issue、Pull Request、その他の公開チャネルに投稿しないでください。

## 報告に含めてほしい情報

問題の調査と再現を容易にするため、可能な範囲で次の情報を含めてください。

- 影響を受けるブランチ、バージョン、または Git Commit
- OS、.NET Runtime のバージョン、デプロイ方法などの実行環境
- 影響を受ける API、機能、またはソースコードの場所
- 問題を再現するための条件と手順
- 不正アクセス、情報漏えい、権限昇格など、想定される影響
- 必要に応じて、検証資料や PoC コード

ログ、設定内容、その他の資料を送信する前に、パスワード、JWT、秘密鍵、ユーザーデータなどの機密情報を必ず削除してください。

## 脆弱性への対応と公開

報告を受け取った後、メンテナーは再現性、影響範囲、実際のリスクに基づいて問題を評価します。

調査と対応の機会を確保するため、メンテナーが問題を確認して対応する前に、脆弱性の詳細を公開しないでください。また、脆弱性を利用して他者のデータやサービスにアクセス、変更、破壊しないでください。

確認された問題については、コードの修正、ドキュメントの更新、セキュリティアドバイザリーの公開などによって対応する場合があります。

本プロジェクトは個人でメンテナンスしているため、一定期間内の回答や修正を保証するものではありません。

## 適用範囲

本ポリシーは、主に本リポジトリで管理されている NihongoHub Server のソースコードおよび公式プロジェクトコンテンツを対象とします。

Fork、独自に変更されたバージョン、第三者が運用するサービスについては、コードの変更、実行環境、設定、運用を含め、それぞれのメンテナーまたは運用者がセキュリティに責任を持つものとします。

第三者による変更やデプロイ環境でのみ発生する問題については、該当するメンテナーまたはサービス運用者に連絡してください。
