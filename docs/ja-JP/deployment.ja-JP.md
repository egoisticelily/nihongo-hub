# NihongoHub Server デプロイガイド

このドキュメントでは、NihongoHub Server の基本的なデプロイ、設定、運用方法について説明します。

> **注意：** NihongoHub Server は現在 Demo 段階であり、本番環境での完全なテストは行われていません。本番環境や重要なデータの保存には使用しないでください。

## 1. 動作環境

NihongoHub Server は ASP.NET Core Minimal API と .NET 10 を使用して開発されています。

使用するパッケージに応じて、必要な実行環境を準備してください。

- フレームワーク依存型のパッケージを使用する場合、対応する .NET 10 Runtime が必要です。
- 自己完結型のパッケージを使用する場合、通常は別途 .NET Runtime をインストールする必要はありません。
- ソースコードからビルドする場合は、.NET 10 SDK をインストールしてください。

ソースコードのディレクトリから直接実行するのではなく、専用のデプロイディレクトリに配置して実行することを推奨します。

## 2. サーバーの起動

実行可能なリリースパッケージを取得し、専用のデプロイディレクトリに配置してください。また、サーバーを実行するユーザーに必要なファイルアクセス権限があることを確認してください。

初回起動時、アプリケーションは実行ディレクトリの下に `Config` ディレクトリを作成します。必要に応じて、デフォルトの設定ファイルも生成されます。

デフォルトのディレクトリ構成は次のとおりです。

```text
アプリケーションディレクトリ/
├── NihongoHub.Server
└── Config/
    ├── config.json
    ├── nihongo.db
    └── initial-admin-credentials.txt
```

実行ファイル名は、対象プラットフォームやビルド方法によって異なる場合があります。

## 3. 初回起動とデフォルト管理者

データベースにユーザーが存在しない場合、アプリケーションはデフォルトの管理者アカウントを自動的に作成します。

- ユーザー名：`admin`
- パスワード：初期化時にランダムに生成されます。

初期ログイン情報は次のファイルに保存されます。

```text
Config/initial-admin-credentials.txt
```

初回起動後、このファイルからログイン情報を取得し、安全な場所に保管してください。

ログイン後は、できるだけ早く管理者パスワードを変更してください。平文の認証情報ファイルが不要になった場合は、削除するか、安全に管理できる場所に保管してください。

**このファイルを公開リポジトリにアップロードしたり、他人と共有したり、信頼できないバックアップ先に保存したりしないでください。**

## 4. 設定ファイル

デフォルトの設定ファイルは次のとおりです。

```text
Config/config.json
```

このファイルでは、サーバーの待ち受けアドレス、ポート、HTTPS、データベースファイル名、JWT などを設定します。

主な設定項目は次のとおりです。

| セクション | 設定項目 | デフォルト値または説明 |
|---|---|---|
| Server | Host | `0.0.0.0` |
| Server | Port | `5000` |
| Server | HttpsEnable | `false` |
| Server | PfxPath | HTTPS 証明書ファイルのパス |
| Server | PfxPassword | 証明書のパスワード |
| Database | FileName | `nihongo.db` |
| Jwt | Key | 初期化時にランダム生成 |
| Jwt | Issuer | `NihongoHub` |
| Jwt | ExpireMinutes | `10080` 分、つまり 7 日 |

アプリケーションが生成した設定ファイルを編集し、必要なフィールド構成とデータ型を維持してください。

現在の設定読み込み処理は、認識できない設定項目を許可しません。アプリケーションが対応していない項目を追加しないでください。

### 4.1 サーバーの待ち受け設定

デフォルト設定は次のとおりです。

- アドレス：`0.0.0.0`
- ポート：`5000`
- HTTPS：無効

`0.0.0.0` は、利用可能なすべてのネットワークインターフェースで待ち受けることを意味します。

デフォルトでは HTTP を使用します。これは信頼できるローカルネットワークやプライベートネットワークでのテストを想定した設定です。追加のセキュリティ対策なしに、デフォルトの HTTP サービスをインターネットに直接公開しないでください。

### 4.2 HTTPS

アプリケーション内蔵の HTTPS を有効にする場合は、次の項目を設定してください。

- `HttpsEnable`：`true` に設定します。
- `PfxPath`：有効な PFX 証明書ファイルのパスを指定します。
- `PfxPassword`：証明書のパスワードを指定します。

証明書ファイルが存在し、アプリケーションの実行ユーザーに読み取り権限があることを確認してください。

また、リバースプロキシをネットワーク境界に設置して HTTPS を提供する方法もあります。この場合、アプリケーションの待ち受けポートへのアクセスを制限し、プロキシとアプリケーション間の通信も適切に保護するか、信頼できるネットワーク内に限定してください。

アカウントのパスワードや Token を送信するクライアントとサーバー間の通信には、保護された接続を使用してください。

### 4.3 データベース

デフォルトのデータベースファイルは次のとおりです。

```text
Config/nihongo.db
```

データベースには LiteDB を使用しています。

データベースにはユーザーアカウントや単語関連のデータが保存されます。不正な読み取りや変更を防ぐため、ファイルへのアクセス権限を適切に制限してください。

## 5. JWT と認証情報の保護

初期化時、アプリケーションはランダムな JWT 署名鍵を生成し、設定ファイルに保存します。

次の点に注意してください。

- `Jwt.Key` を公開しないでください。
- 設定ファイルを公開リポジトリにアップロードしないでください。
- 証明書、証明書のパスワード、初期管理者の認証情報をコミットしないでください。
- JWT 署名鍵を変更すると、以前の鍵で署名された Token は無効になります。
- デフォルトの Token 有効期間は 7 日です。

現在のバージョンでは、ユーザーのパスワードを変更しても、そのユーザーに以前発行された Token は自動的に無効になりません。そのため、パスワード変更は、既存のすべてのログインセッションを直ちに終了させる方法ではありません。

## 6. ネットワークセキュリティに関する推奨事項

インターネットや信頼できないネットワークでデプロイする前に、少なくとも次の対策を検討してください。

- HTTPS を使用してクライアントとサーバー間の通信を保護する。
- ファイアウォールやリバースプロキシを使用して、不要なネットワークアクセスを制限する。
- データベースファイル、設定ファイル、その他の内部ファイルをインターネットに公開しない。
- アプリケーションと設定ディレクトリのファイルアクセス権限を制限する。
- データベースと必要な設定ファイルを定期的にバックアップする。
- 信頼できない端末、ログ、公開ディスカッションにパスワードや Token を保存しない。

現在のサーバー実装には、ログインリクエストに対する API 単位のレート制限は実装されていません。インターネットに公開する場合は、リバースプロキシやネットワーク境界でアクセス制限などの対策を追加することを検討してください。

## 7. バックアップとアップデート

アプリケーションの更新や設定変更を行う前に、サービスを停止し、次のファイルをバックアップすることを推奨します。

- `Config/nihongo.db`
- `Config/config.json`
- 必要な証明書ファイルと関連設定

バックアップは、適切なアクセス制限が設定された場所に保存してください。

更新時は、新しいバージョンのアプリケーションファイルに置き換え、引き続き使用する設定ファイルとデータベースを保持してください。

本プロジェクトはまだ Demo 段階です。データベース構造や設定形式が変更される可能性があります。アップデート前にデータをバックアップし、すべてのバージョン間で完全な互換性があると想定しないでください。

## 8. トラブルシューティング

### アプリケーションが起動しない

次の項目を確認してください。

- 実行環境が必要な .NET Runtime の要件を満たしているか。
- アプリケーションディレクトリに必要なファイルアクセス権限があるか。
- `Config/config.json` が有効な JSON 形式か。
- 設定項目とデータ型が現在のアプリケーションの要件に合っているか。
- HTTPS を有効にしている場合、PFX ファイルが存在し、証明書のパスワードが正しいか。

### API に接続できない

次の項目を確認してください。

- アプリケーションが正常に起動しているか。
- 待ち受けアドレスとポートが正しいか。
- ファイアウォールで対象ポートへの通信が許可されているか。
- リバースプロキシを使用している場合、転送設定が正しいか。

### ログインできない

管理者のユーザー名とパスワードが正しいか確認してください。

初回起動の場合は、次のファイルが生成されているか確認してください。

```text
Config/initial-admin-credentials.txt
```

このファイルが存在しない場合でも、デフォルトのパスワードが空であるとは限りません。アプリケーションの起動ログとデータベースの初期化状態を確認してください。
