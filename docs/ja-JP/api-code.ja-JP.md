# API Code の番号ルール

> **仕様のバージョン：** 0.1.0 Beta  
> **対象：** NihongoHub バックエンド HTTP API

API Code は、NihongoHub が独自に決めたアプリケーション用のコードです。API の処理結果やエラーの理由を表します。クライアントは、このコードを見て結果を判断できます。

API Code と HTTP ステータスコードは別のものです。HTTP ステータスコードは HTTP のルールに従い、リクエストがどのように処理されたかを表します。API Code は、NihongoHub が決めた具体的な結果を表します。クライアントは API Code を使ってエラーの内容を判断してください。2つを同じものとして扱わないでください。

## 1. 番号のルール

API Code には整数を使います。機能ごとに番号の範囲を分けます。

| 番号の範囲 | 種類 |
|---|---|
| `0` | 成功 |
| `1000–1099` | リクエストの一般的なエラー |
| `1100–1199` | 認証エラー |
| `1200–1299` | 権限エラー |
| `2000–2099` | ユーザー管理 |
| `3000–3099` | 単語管理 |
| `4000–4099` | 単語帳の管理 |
| `5000–5099` | 学習とテスト |
| `9000–9099` | サーバー内部のエラー |

一度決めた番号の意味は、勝手に変えてはいけません。ここに書かれていない番号は、今後の機能追加のために残します。

## 2. 現在の API Code

### 2.1 成功

| Code | 意味 |
|---:|---|
| `0` | 処理に成功しました |

### 2.2 リクエストの一般的なエラー（1000–1099）

| Code | 意味 |
|---:|---|
| `1000` | リクエストのパラメーターが正しくありません |
| `1001` | リクエスト本文が空です |
| `1002` | JSON の形式が正しくありません |
| `1003` | 必要なパラメーターがありません |
| `1004` | パラメーターの値が正しくありません |
| `1005` | 対応していないリクエスト形式です |

### 2.3 認証エラー（1100–1199）

| Code | 意味 |
|---:|---|
| `1100` | 認証に失敗しました |
| `1101` | ユーザー名またはパスワードが正しくありません |
| `1102` | Token がありません |
| `1103` | Token が無効です |
| `1104` | Token の有効期限が切れています |
| `1105` | Token はまだ使えません |
| `1106` | Token Claims が正しくありません |
| `1107` | ユーザーの認証情報はもう有効ではありません |

追加ルール：

- ログイン時、ユーザー名が存在しない場合とパスワードが間違っている場合は、どちらも `1101` を返します。どちらが原因かはクライアントに知らせません。
- ユーザーが無効にされた場合や削除された場合、またはデータベースの役割と Token の役割が一致しない場合、認証に失敗し、`1107` を返します。
- データベースの検索でエラーが起きた場合、認証エラーとして扱いません。サーバー内部エラーのコードを使います。

### 2.4 権限エラー（1200–1299）

| Code | 意味 |
|---:|---|
| `1200` | この操作を行う権限がありません |
| `1201` | 管理者の権限が必要です |
| `1202` | このリソースにアクセスする権限がありません |

### 2.5 ユーザー管理（2000–2099）

| Code | 意味 |
|---:|---|
| `2000` | ユーザーの操作に失敗しました |
| `2001` | ユーザーが見つかりません |
| `2002` | このユーザー名はすでに使われています |
| `2003` | ユーザーは無効になっています |
| `2004` | ユーザーのデータが正しくありません |
| `2005` | このユーザーに対して、この操作はできません |

ログイン時、アカウントの状態を理由に `2003` を直接返してはいけません。認証エラーのルールに従ってください。

### 2.6 単語管理（3000–3099）

| Code | 意味 |
|---:|---|
| `3000` | 単語の操作に失敗しました |
| `3001` | 単語が見つかりません |
| `3002` | 単語のデータが正しくありません |
| `3003` | この単語を操作する権限がありません |
| `3004` | 単語に関係する操作に失敗しました |

### 2.7 単語帳の管理（4000–4099）

| Code | 意味 |
|---:|---|
| `4000` | 単語帳の操作に失敗しました |
| `4001` | 単語帳が見つかりません |
| `4002` | 単語帳のデータが正しくありません |
| `4003` | この単語帳を操作する権限がありません |
| `4004` | 単語帳に関係する操作に失敗しました |
| `4005` | この単語はすでに単語帳に追加されています |

### 2.8 学習とテスト（5000–5099）

この番号の範囲は、今は使いません。学習とテストの機能を開発するときに、使うコードを決めます。

### 2.9 サーバー内部のエラー（9000–9099）

| Code | 意味 |
|---:|---|
| `9000` | サーバー内部でエラーが発生しました |
| `9001` | データベースの操作に失敗しました |
| `9002` | 原因がわからないエラーです |
| `9003` | サーバーの設定に問題があります |
| `9004` | 内部の処理に失敗しました |

サーバー内部エラーの詳しい情報は、サーバーのログにだけ記録してください。API の応答で、例外が起きた場所を示す詳しい情報（スタックトレース）、データベースのパス、その他の内部情報をクライアントに見せてはいけません。

## 3. 使い方のルール

- `code = 0` は処理が成功したことを表します。0 以外の値は、具体的なエラーや失敗を表します。
- 同じ Code は、いつも同じ意味で使ってください。別の API で、同じ Code に別の意味を持たせてはいけません。
- 複数のデータをまとめて処理し、一部だけ成功した場合の応答方法とエラー情報は、それぞれの API で別に決めてください。
